# Docker Compose 部署验收

本指南用于新部署、升级或备份恢复后的检查，不代表任何实例已通过验收。命令在仓库根目录执行；使用 GHCR 镜像或本地覆盖文件时，带上与启动服务相同的 Compose 文件，详见 [运维指南](operations.md#部署配置与数据)。

## 容器与数据卷

```sh
docker compose ps
docker compose logs --tail=100 llm-dashboard
docker inspect llm-dashboard --format '{{.State.Health.Status}}'
docker inspect llm-dashboard --format '{{range .Mounts}}{{if eq .Destination "/data"}}{{.Name}}{{end}}{{end}}'
```

确认容器为 `healthy`，日志没有持续报错，`/data` 挂载到预期卷。升级或恢复时对照此前记录的配置数量、历史和图形，避免误用新建空卷。

停止服务后的完整归档或恢复卷，可按 [恢复指南](operations.md#恢复到新卷与回滚) 检查 SQLite 完整性。不要为了验收直接复制运行中的数据库，也不要启动第二个应用容器写入同一卷。

## 页面与访问权限

以下地址适用于默认端口，在部署主机执行；从其他设备访问时，将 `127.0.0.1` 换成部署主机的实际地址。

```sh
curl --fail http://127.0.0.1:18765/
curl --fail http://127.0.0.1:18765/admin
curl --fail http://127.0.0.1:18765/api/auth/status
curl --fail http://127.0.0.1:18765/api/dashboard
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18765/api/admin/cards
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:18765/api/guest/status
```

页面和公开 API 应能正常访问；未携带管理员凭据的管理接口应返回 `401`，已关闭的访客检测接口应返回 `410`。

在浏览器检查：

1. 大盘、后台和静态资源正常加载，桌面和手机宽度下可用。
2. 初次部署打开 `/admin`，输入并确认 12–256 字符的管理密码，再登录；已有实例使用原密码登录，不重新初始化。
3. 同一浏览器、同一主机地址下，刷新或从首页返回后台可恢复未到期会话；主动退出后管理接口不可访问。
4. 公开页面保持只读，刷新或查看详情不会触发上游检测。
5. 未公开卡片的历史、SVG 和缩略图无法通过公开接口读取，公开结果不泄露凭据。
6. “系统设置”可保存检测并发与三类保留天数；刷新页面后值不丢失，保存无需重启。
7. “修改管理密码”要求当前密码和新密码确认；成功后原会话失效，使用新密码可重新登录。

外网访问时使用 HTTPS 反向代理，并确认实际端口和访问地址与部署配置一致。

## 配置、任务与统计

升级或恢复后先检查数据，再恢复自动检测：

- 原有卡片、模型、检测计划、启停状态及历史符合预期。
- 未配置 API Key 或尚未启用的模型保持暂停。
- 无样本、上游未提供缓存明细、非流式首返等情况显示空状态，不补造指标。
- 已有图形与缩略图可以查看，达到保留期限的产物按配置清理。
- 管理员可以查看任务队列和执行状态，检测结果区分接口成功与题目判定。
- 检测并发支持 1–8，降低并发不打断现有请求；三类保留天数支持 1–3650，变更在下一轮每小时例行清理时执行。

如需验证实际检测，在后台确认卡片和模型配置后执行预期的检测，观察结果、错误原因及资源使用；该操作会调用上游 API。验证自动计划前确认卡片、模型和具体检测项目均已开启。

验收完成后，记录镜像版本、实际卷名、备份位置和发现的问题，保存在部署方的运维记录中。需要回滚时同时恢复匹配版本的镜像与数据，按 [备份与回滚指南](operations.md) 操作。
