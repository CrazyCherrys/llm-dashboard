# LLM Dashboard

自托管的模型接口监控站。管理员统一配置模型、自定义分类和提示词模板，后台按各自间隔执行逻辑题与 SVG 图形测试；访客只读查看模型指标、检测历史和图形结果。

一张大盘卡片可包含多个模型，共用卡片的 API 地址和密钥。每个模型独立配置检测参数、提示词模板和检测计划；逻辑结果分别展示，图形结果合并展示并标注来源模型。分类名称完全自定义，不预设系列，按卡片整理和筛选。同一个模型 ID 可以添加多份配置。支持 OpenAI 兼容的 Responses 和 Chat Completions 协议。

## 当前能力

- 后台统一新增、编辑、复制、启停、隐藏或归档模型，API Key 脱敏展示；分类支持新增、重命名、排序和删除。
- 每个模型设置协议、思考强度、重试上限、超时；逻辑检测和图形检测分别选择提示词模板、设置间隔。
- 提示词模板支持新增、编辑、复制和归档，包含提示词与判定标准；每轮检测保留当次模板版本。
- 后台持续自动检测，单项任务防重入、有限队列和有限并发；服务重启不重放中断请求。
- 首页概览展示完整近 24 小时的逻辑测试通过率；卡片汇总全部模型的缓存率、请求成功率、平均首次有效返回时间和请求时间条，各模型分别展示最近 50 轮逻辑检测，下方合并图形缩略图。
- 图形生成后进行 SVG 安全校验、静态截图及多帧视觉审核；点击缩略图查看动画和测试详情。
- SQLite WAL 持久化配置、请求尝试和历史结果，SVG / PNG 保存在独立文件目录。
- 访客提交接口已关闭；打开或刷新大盘不会触发模型请求。

## Docker Compose 部署

需要 Docker Engine / Docker Desktop 和 Docker Compose。Windows 使用 Linux 容器。

```sh
git clone https://github.com/CrazyCherrys/llm-dashboard.git
cd llm-dashboard
```

已有 `manxue-ai` 实例请先按 [项目改名与原数据卷迁移](docs/operations.md#项目改名与原数据卷迁移) 停止旧服务并配置原数据卷，再启动新服务，保留管理密码、模型配置和历史。

首次启动需要设置 12–256 字符的管理密码。Linux / macOS（Bash）：

```bash
read -r -s -p "Initial admin password: " ADMIN_TOKEN
echo
export ADMIN_TOKEN
docker compose up -d --build
unset ADMIN_TOKEN
```

Windows（PowerShell 7）：

```powershell
$env:ADMIN_TOKEN = Read-Host 'Initial admin password' -MaskInput
docker compose up -d --build
Remove-Item Env:ADMIN_TOKEN
```

本机首页：<http://127.0.0.1:18765/>；后台：<http://127.0.0.1:18765/admin>。

Compose 默认绑定 `0.0.0.0:18765`，局域网设备访问 `http://服务器IP:18765/`。当前工作区部署机器的地址为 <http://192.168.3.14:18765/>，其他机器以实际网络配置为准。

`ADMIN_TOKEN` **只用于没有管理密码时的初始化**，不是模型 API Key，也不会覆盖数据库中的既有密码。清除环境变量后，可以运行 `docker compose up -d --force-recreate`，从容器配置中移除初始化密码。

```sh
docker compose ps
docker compose logs --tail=100 llm-dashboard
```

数据保存在 Compose 命名卷中，默认卷名为 `llm-dashboard-data`，不随仓库目录变化。重建镜像或容器不会清空配置和历史。`docker compose down -v` 会删除数据卷，不要用于普通更新。

## GitHub Actions 与 GHCR 镜像

推送到 `main` 后，GitHub Actions 自动构建 Linux `amd64` / `arm64` Docker 镜像并发布到 `ghcr.io/crazycherrys/llm-dashboard`；推送 `v*` 版本标签可发布版本镜像，`latest` 仅由 `main` 更新。拉取请求和非 `main` 的手动运行只验证、不发布。工作流使用 GitHub 自动提供的 `GITHUB_TOKEN`，无需另外添加镜像发布密码。

首次启用需要完成仓库更名、GitHub 登录与代码推送，并确认 Actions 可用。第一次发布的 GHCR 包默认私有，需要在包设置中改为公开，或在部署机器上使用有读取权限的令牌登录。详细操作见 [GitHub Actions 发布与 GHCR 部署](docs/github-actions.md)。

使用预构建镜像时，通过 `compose.ghcr.yaml` 覆盖镜像并执行 `pull` / `up -d --no-build`。已有迁移实例必须同时显式加载 `compose.override.yaml`，保留原数据卷；完整命令见上述指南。此工作流发布镜像，服务器更新仍由部署者执行。

## 管理后台操作

1. 使用管理密码登录 `/admin`。
2. 点击“新增卡片”：填写卡片名称（如 CodeX-Pro）、共享 API 地址和 Key，设置分类、公开状态和排序。分类名称自定义，也可保持“未分类”。
3. 保存卡片后自动打开“新增模型”。填写真实模型 ID、显示名称、协议和思考强度；重试、超时等放在高级设置中。
4. 为逻辑与图形检测分别选择提示词模板、设置独立间隔。可先在“提示词模板”中创建自己的模板。默认逻辑检测 10 分钟、图形检测关闭且间隔 45 分钟；新增或复制的模型默认暂停。
5. 在同一卡片继续“添加模型”或“复制模型”。添加三个模型，首页同一卡片就显示三个独立逻辑区，下方合并展示全部模型最近 50 张图形；卡片保留图形拖动条，聚焦缩略图后可用左右键浏览，按 Enter 打开详情。
6. 可先“测逻辑 / 测图形”验证，再启用自动检测。“暂停整卡”保留子模型开关，取消排队任务，已运行任务正常结束；“恢复整卡”只恢复原先启用的模型。共享连接、分类和公开状态在“卡片设置”中修改。

空卡片只在后台显示；复制模型仅复制参数、模板和计划，不复制历史。重命名分类不影响历史；删除分类将卡片移到“未分类”。没有公开非空卡片的分类不出现在首页。
API 地址填写基础路径，例如 `https://api.example.com/v1`。后端追加 `/responses` 或 `/chat/completions`；填写完整端点时会归一化为基础路径。使用 HTTPS，只有本机测试地址支持 HTTP。

编辑已有模型时，密钥留空表示保留原值。更换 API 地址必须重新填写对应 API Key。暂停模型或检测项目会取消尚未发送的排队任务；已经运行的任务继续完成并保存结果。管理员立即检测可以用于验证暂停中的配置，仍受防重入和队列容量限制。

“隐藏”只影响公开页面，不停止后台检测；“暂停”停止自动调度，仍可公开历史。归档后从常规列表和公开页面移除，历史在保留期限内仍可由管理员按检测 ID 查询。

后台使用 `HttpOnly`、`SameSite=Lax` 的会话 Cookie。在同一浏览器、同一主机地址登录后，返回首页、刷新或重新进入后台会恢复登录，最长保留两小时；主动退出或到期后需要重新登录。IP 地址与 `localhost` 属于不同 Cookie 主机，切换地址不会继承登录。会话保存在服务内存中，服务重启会使登录失效，已保存的管理密码不变。API 客户端仍支持 Bearer 令牌。

## 提示词模板

后台点击“提示词模板”，填写自定义名称、检测类型和完整提示词；新增或编辑模型时分别选择逻辑题、图形模板，可展开预览内容。复制模型会沿用所选模板。

逻辑题支持四种判定方式：完整答案匹配（规范化字符、空白和英文大小写）、独立数字匹配、包含指定文本（区分大小写）、仅记录不评分。数字与文本匹配不等同于语义评分；要求严格答案时，应在题目中要求只输出答案并选择完整答案匹配。未评分记录单独显示，不计入正确率。

图形模板填写自己的视觉审核标准，可选择是否要求动画。输出仍为安全、独立的 SVG；系统补充输出要求与可见校验码。提示词中的 `{scene}` 与 `{nonce}` 可分别替换为随机场景、当次校验码，普通 CSS 大括号不会被替换。视觉审核使用当前模型，需要它支持图片输入。

编辑模板后版本递增，引用它的模型在后续新建检测时使用新版本；已排队和历史检测保留原题目、答案规则与审核标准，不重新评分。仍被模型选择的模板不能归档，需先更换选择；归档保留历史。

## 指标和颜色定义

首页“逻辑测试 · 近 24 小时”按每份模型配置统计全部已完成逻辑测试，随分类筛选，不受最近 50 轮限制。卡片请求指标默认使用最近 24 小时，在“统计说明与更新时间”中可切换 1 / 6 / 24 小时；该切换不改变逻辑概览。时间显示为北京时间（UTC+8）。

| 指标 | 计算方式 |
| --- | --- |
| 缓存率 | 有有效缓存数据的请求：缓存命中输入 Token 总和 ÷ 对应输入 Token 总和。缺失不当成 0；同时提供样本和覆盖信息 |
| 请求成功率 | 成功的主检测请求尝试数 ÷ 已结束的主检测请求尝试数，包含重试及已发出后中断的请求，排除视觉审核 |
| 平均首次返回 | 成功主请求中，从发出请求到首段非空有效内容的平均时间；明确提供的推理内容也可作为首段内容 |
| 概览逻辑通过率 | 近 24 小时已完成逻辑检测的通过数 ÷ 已评分数；请求失败、未评分和图形测试不计入 |
| 各模型逻辑正确率 | 最近 50 轮中，通过数 ÷ 已评分数；请求失败和未评分不计入 |

上游只返回完整 JSON 时，保留总耗时，首次返回显示“未提供”。没有数据时不显示虚构的 `0%` 或 `0 秒`。

模型请求历史展示最近 6 小时，每 10 分钟一格：可用性条区分全部成功、部分失败、全部失败和无样本；速度条显示成功请求的平均首次返回时间。

| 速度颜色 | 首次有效返回耗时 |
| --- | --- |
| 绿色 | 小于 10 秒 |
| 黄色 | 10 秒至小于 30 秒 |
| 橙色 | 30 秒至小于 50 秒 |
| 红色 | 50 秒及以上 |
| 灰色 | 没有可测量的成功样本 |

真正的超时表现为失败状态，不伪造首次返回时间。模型逻辑历史每格表示一轮：通过为绿、答错为红、排队 / 运行中为黄、请求失败 / 中断等无有效结果为灰。

默认糖果模板延续独立数字 `21` 的边界匹配；旧记录仍保留 `candy-v1-independent-21`，新检测使用 `template-{id}-v{revision}-{rule_type}` 记录规则。概览混有多个模板版本时会注明，使用不同题目的模型不作为统一排名。通过安全校验的 SVG 可以展示；缩略图或视觉审核失败有单独状态，不代表模型请求失败。这些任务的结果不证明模型身份，也不代表模型整体能力。

## 调度和调用成本

- 服务持续运行时才会执行自动检测；同一数据目录只支持一个服务进程。
- 同一模型的同一种检测最多有一个排队 / 执行中任务。慢请求跨过下一次计划时间时不会积压补跑；逻辑和图形可以独立排队。
- 队列最多保留 32 个排队任务，默认工作并发为 2，Chromium 渲染并发为 1。
- `retry_count` 是首次请求之外的额外重试次数。鉴权、参数等明确错误不反复重试，临时网络或服务错误按退避重试。
- 总检测预算约束生成、重试退避、渲染锁等待、截图及视觉审核。截图阶段至多 30 秒，审核请求至多 120 秒，均不超过整轮剩余预算。
- 建连、TLS 和等待响应头使用配置的首次返回等待预算，并受剩余总预算限制，没有固定的 20 秒响应头上限。响应头到达后仍继续扣除已等待时间，首次有效内容和流式读取分别受首返、空闲及总预算约束。
- 视觉审核使用同一模型配置，需要支持图片输入，会额外消耗 API 额度；审核请求单独记录，不混入模型主指标。生成与重试也会消耗额度。
- 重启时未完成任务标记为中断，不自动重放已经可能计费的请求；以后按正常调度继续。

## 环境变量

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `HOST` | `127.0.0.1`，容器内 `0.0.0.0` | 监听地址 |
| `PORT` | `8765` | 应用端口；Compose 对外映射 18765 |
| `DATA_DIR` | `app/data`，容器内 `/data` | 数据库、实例锁和图形产物目录 |
| `DATA_VOLUME_NAME` | `llm-dashboard-data` | 仅 Compose：默认新建数据卷的名称；沿用已有外部卷时使用操作指南中的覆盖文件 |
| `LLM_DASHBOARD_IMAGE` | `ghcr.io/crazycherrys/llm-dashboard:latest` | 仅 `compose.ghcr.yaml`：选择已发布的镜像标签或摘要 |
| `ADMIN_TOKEN` | 空 | 仅首次初始化管理密码 |
| `WORKER_CONCURRENCY` | `2` | 工作线程数，支持 1–8 |
| `RUN_RETENTION_DAYS` | `90` | 已结束检测及请求指标保留天数 |
| `ARTIFACT_RETENTION_DAYS` | `30` | SVG、缩略图和旧版内嵌 SVG 保留天数 |
| `OUTPUT_RETENTION_DAYS` | `30` | 完整模型回答保留天数 |

保留天数至少为 1；回答和产物的实际保留期限不超过检测记录期限。调度器每小时检查过期数据，分批清理已完成记录，保留运行中的任务。首页展示最近 50 轮 / 张不等于数据库仅保存 50 条。清理后完整回答或图形可能已不可用，而请求指标仍保留到记录保留期限。

SQLite 文件位于本机持久化卷，启用 WAL、外键和短事务。API Key 保存在 SQLite，使用文件权限保护，**没有数据库加密**。管理密码为带随机盐的 PBKDF2-SHA256 哈希。不要发布数据库、数据卷、日志、备份或真实环境文件。

Compose 可通过环境变量覆盖并发和保留期限，设置后执行 `docker compose up -d --force-recreate`。提高并发前先验证内存和上游限制。对公网开放时在主机上配置 HTTPS 反向代理。

## 本地运行和测试

支持 Linux / macOS、Python 3.11+。Windows 使用 Docker 或 WSL。

```sh
cd app
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium
python server.py
```

Linux 缺少浏览器系统依赖时运行 `python -m playwright install --with-deps chromium`。默认在 <http://127.0.0.1:8765/admin> 首次设置密码，数据写入 `app/data/`。绑定非回环地址前必须已有密码或提供 `ADMIN_TOKEN`。

```sh
cd app
python3 -m unittest discover -s tests -v
```

测试使用临时数据库和本机模拟上游，不需要真实 API Key。针对工作区备份的迁移测试在没有该备份时跳过；另有独立旧结构夹具验证历史迁移。

浏览器交互检查单独运行（需要已安装 Playwright Chromium）：

```sh
cd app
python3 tests/ui_interactions.py
```

检查使用独立的临时页面服务和模拟记录，覆盖悬浮预览、弹窗关闭与未保存保护、手机记录返回和翻页、保存反馈、图片滑动、检测进度以及刷新时的焦点与节点保留，不修改正式配置或调用模型。

## 升级、备份与恢复

现有 v4 数据库升级到 v5 只增加卡片分类、子模型排序并解除单模型限制，不自动合并、搬移或清空现有配置和历史。缺少缓存和首次返回指标的旧记录保持未知。

升级前保留旧镜像并备份数据库和 `artifacts/`。WAL 模式下不要只复制正在写入的数据库主文件；使用 SQLite 在线备份 API，或停服务后备份完整数据目录。恢复时数据库和图形文件应匹配，并恢复容器用户读写权限。

详细操作见 [迁移、备份与回滚指南](docs/operations.md)。只换回旧镜像不能保证它读取新数据库，应恢复配套的旧版数据备份。

接口、前端交互和统计约定见 [实现与接口说明](docs/implementation.md)。

## 模型管理升级

数据结构版本 3 自动把原先同一渠道下的多个模型拆成独立配置，保留模型、检测、请求、图形和计划编号以及管理密码。现有模型先归入“未分类”，不按模型名称自动生成分类。原有单模型卡片沿用标题；多模型卡片使用“原卡片标题 · 模型显示名称”区分。暂停、隐藏和归档状态保留。

部署前备份 SQLite 和产物目录；升级迁移在事务内执行，重复启动不会重复拆分。回退旧版时应同时还原升级前镜像与数据库备份，不能让旧版继续写升级后的数据库。自动检测和已有保留期限继续适用。

浏览器回归检查可分别运行 `python tests/ui_interactions.py` 和 `python tests/model_management_ui.py`。后者使用临时数据库与真实 HTTP 服务，但不启动后台调度或调用上游模型。

数据结构版本 4 增加提示词模板，并为现有逻辑、图形计划关联对应默认模板，不改变原检测间隔、启停状态、连接密钥、管理密码和历史结果。升级前同样需要配套的数据库、产物与镜像备份。

### 多模型卡片（版本 5）

卡片分类独立于旧模型分类，现有卡片默认未分类，可在后台重新选择。旧卡片及其模型保留原结构；需要重建时由管理员自行归档。卡片请求指标按全部主请求及 Token 原始数据汇总，不平均模型百分比。近 24 小时逻辑概览仍按每个模型计算，并标注卡片 / 模型。图形详情展示当次生成的卡片名称、模型显示名与真实 ID；逻辑前后切换仅在同一模型内，图形前后切换可跨同一卡片内的模型。卡片保留两条请求时间条，模型区仅展示名称、正确率、模板简称、检测状态和结果条。点击模型名称查看参数与详细计数，并可进入逻辑历史；统计样本与口径收进“统计详情”。图形区不再显示底部左右按钮、回到最新、长说明或单独的图形历史入口。
