# LLM Dashboard

自托管的模型接口监控站。管理员配置模型、分类和提示词模板，后台定时执行逻辑题与 SVG 图形检测；访客只读查看接口指标、检测历史和图形结果。

每张卡片可添加多个模型，共用 API 地址和密钥。各模型独立设置请求参数、提示词模板和检测计划，支持 OpenAI 兼容的 Responses 与 Chat Completions 协议。

## 功能

- **模型管理**：新增、编辑、复制、启停和归档模型，设置卡片公开状态、分类与排序。
- **定时检测**：逻辑和图形分别设置模板与间隔，支持立即检测、有限重试和超时控制。
- **提示词模板**：自定义题目与判定标准，按版本保存每轮检测使用的模板。
- **监控大盘**：查看近 24 小时逻辑通过率、缓存率、请求成功率、首次有效返回时间和最近检测记录。
- **图形结果**：SVG 安全校验、静态缩略图与多帧视觉审核，支持动画预览和详情浏览。
- **数据持久化**：SQLite 保存配置与历史，独立目录保存 SVG / PNG；刷新大盘不会触发模型请求。
- **网页设置**：首次在后台创建管理密码，登录后可修改密码、检测并发及数据保留天数。

## Docker Compose 部署

需要 Docker 和 Docker Compose v2，以下操作在仓库根目录执行。部署方式有两种：拉取预构建镜像，或通过 Dockerfile 本地构建。

```sh
git clone https://github.com/CrazyCherrys/llm-dashboard.git
cd llm-dashboard
```

选择下方一种方式启动即可，管理密码和运行设置均在网页中填写，无需创建配置文件。

### 使用预构建镜像

先确认 GHCR 中已有可用镜像；私有镜像需要先登录。镜像发布、标签与登录方法见 [GitHub Actions 与 GHCR 部署指南](docs/github-actions.md)。

```sh
docker compose -f compose.yaml -f compose.ghcr.yaml pull llm-dashboard
docker compose -f compose.yaml -f compose.ghcr.yaml up -d --no-build
docker compose -f compose.yaml -f compose.ghcr.yaml ps
docker compose -f compose.yaml -f compose.ghcr.yaml logs --tail=100 llm-dashboard
```

默认镜像为 `ghcr.io/crazycherrys/llm-dashboard:latest`，可通过 `LLM_DASHBOARD_IMAGE` 指定已发布的版本标签或镜像摘要。支持 Linux `amd64` / `arm64`。

### 从源码构建镜像

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 llm-dashboard
```

### 访问与初始化

- 首页：<http://127.0.0.1:18765/>
- 管理后台：<http://127.0.0.1:18765/admin>
- 其他设备：`http://服务器IP:18765/`，Compose 默认绑定 `0.0.0.0:18765`。

首次打开 `/admin`，输入并确认 12–256 字符的管理密码，然后登录后台。首次启动后立即打开后台完成设置，对公网使用 HTTPS。

Compose 首次启动会自动创建 `llm-dashboard-data` 数据卷，挂载到容器内的 `/data`，保存配置、检测历史和图形文件。重建容器或镜像会保留这些数据；**`docker compose down -v` 会删除数据卷及其中的数据。**

## 管理后台

1. 使用管理密码登录 `/admin`，点击“新增卡片”，填写卡片名称、共享 API 地址和 Key，并设置分类、公开状态与排序。
2. 保存后添加模型，填写真实模型 ID、显示名称、协议和思考强度；重试、超时等参数在高级设置中调整。
3. 为逻辑与图形分别选择提示词模板和检测间隔。默认逻辑检测间隔 10 分钟，图形检测关闭且间隔 45 分钟；新增或复制的模型默认暂停。
4. 先用“测逻辑 / 测图形”验证配置，再启用自动检测。同一卡片可继续添加或复制模型；复制只保留配置，不复制历史。
5. “暂停整卡”保留子模型开关，取消排队任务，已运行任务正常结束；“恢复整卡”只恢复原先启用的模型。

API 地址填写基础路径，例如 `https://api.example.com/v1`，后端自动追加 `/responses` 或 `/chat/completions`。使用 HTTPS，只有本机测试地址支持 HTTP。编辑密钥时留空表示保留原值，更换 API 地址必须重新填写对应 Key。

“隐藏”只影响公开页面，后台仍会检测；“暂停”停止自动调度，历史仍可公开；“归档”从常规列表和公开页面移除，历史保留到设定期限。空卡片只在后台显示，没有公开非空卡片的分类不出现在首页。

登录会话最长保留两小时，同一浏览器、同一主机地址下刷新后可恢复登录。服务重启、会话到期或主动退出后需要重新登录，已保存的管理密码不变。

## 系统设置

登录后台后打开“系统设置”，直接在网页修改以下选项：

| 设置 | 默认值 | 范围 / 用途 |
| --- | --- | --- |
| 检测并发 | 2 | 1–8；单人使用可设为 1 |
| 检测记录保留天数 | 90 | 1–3650；包括检测记录和请求指标 |
| 图形保留天数 | 30 | 1–3650；SVG 和缩略图 |
| 完整回答保留天数 | 30 | 1–3650；模型完整回答 |

例如单人使用可设置为并发 `1`、检测记录 `30` 天、图形和完整回答各 `7` 天。设置保存在 SQLite 中，保存后无需重启容器；降低并发不会打断正在执行的检测，保留期限调整在下一轮每小时例行清理时执行。回答和图形的实际保留期限不超过检测记录期限，运行中任务不清理。

在“修改管理密码”中输入当前密码、新密码并确认；新密码须为 12–256 字符。修改成功后所有登录会话失效，需要使用新密码重新登录。

## 提示词模板

在后台“提示词模板”中填写名称、检测类型、提示词和判定标准，再为模型选择对应模板。

逻辑题支持完整答案匹配、独立数字匹配、包含指定文本和仅记录不评分。完整答案匹配会规范化字符、空白及英文大小写；文本包含匹配区分大小写。数字与文本匹配不等同于语义评分，未评分记录不计入正确率。

图形模板可自定义视觉审核标准及是否要求动画，输出为安全、独立的 SVG。`{scene}` 与 `{nonce}` 分别替换为随机场景和当次校验码，普通 CSS 大括号保留。视觉审核使用当前模型，需要支持图片输入，并额外消耗 API 额度。

编辑模板会生成新版本，后续检测使用新版本，已排队和历史检测保留原模板与判定。仍被模型引用的模板需先更换选择，才能归档。

## 指标说明

首页逻辑概览统计近 24 小时全部已完成的逻辑检测，随分类筛选。卡片请求指标默认统计近 24 小时，可切换为 1 / 6 / 24 小时；切换不影响逻辑概览。时间显示为北京时间（UTC+8）。

| 指标 | 计算方式 |
| --- | --- |
| 缓存率 | 有有效缓存数据的请求中，缓存命中输入 Token 总和 ÷ 对应输入 Token 总和；缺失数据不当成 0 |
| 请求成功率 | 成功主检测请求尝试数 ÷ 已结束主检测请求尝试数，包含重试和已发送后中断的请求，排除视觉审核 |
| 平均首次返回 | 成功主请求从发出到首段非空有效内容的平均时间，明确返回的推理内容也可计入 |
| 概览逻辑通过率 | 近 24 小时已完成逻辑检测的通过数 ÷ 已评分数，请求失败与未评分不计入 |
| 各模型逻辑正确率 | 最近 50 轮逻辑检测的通过数 ÷ 已评分数，请求失败与未评分不计入 |

卡片指标汇总全部子模型的请求与 Token 原始数据，不平均模型百分比。上游只返回完整 JSON 时，保留总耗时，首次返回显示“未提供”；没有数据时不显示虚构的 `0%` 或 `0 秒`。

请求历史展示最近 6 小时，每 10 分钟一格。可用性条区分全部成功、部分失败、全部失败和无样本；速度条使用成功请求的平均首次有效返回时间：

| 速度颜色 | 首次有效返回耗时 |
| --- | --- |
| 绿色 | 小于 10 秒 |
| 黄色 | 10 秒至小于 30 秒 |
| 橙色 | 30 秒至小于 50 秒 |
| 红色 | 50 秒及以上 |
| 灰色 | 没有可测量的成功样本 |

逻辑历史每格表示一轮：通过为绿、答错为红、排队 / 运行中为黄、请求失败 / 中断等无有效结果为灰。图形预览或视觉审核失败有单独状态，不等同于模型请求失败。不同题目的模型不作为统一排名，检测结果也不证明模型身份或整体能力。

## 容器配置

容器内应用端口为 `8765`，Compose 对外映射 `18765`。默认限制为 1 CPU、1 GB 内存和 256 个进程，Chromium 渲染并发为 1；提高检测并发前先验证内存和上游限制。同一数据卷只支持一个服务进程。

普通部署使用默认 Compose 即可。需要指定预构建镜像时，可使用 `LLM_DASHBOARD_IMAGE` 选择已发布的标签或摘要；密码、并发和数据保留期限在网页管理。首页最近 50 轮 / 张不等于数据库只保存 50 条。

## 运行说明

API Key 保存在 SQLite 中，没有数据库加密；管理密码保存为加盐哈希。保护数据卷和日志，不要公开或提交这些文件。

后台仅在服务运行时自动检测，同一模型同一种检测不会重复排队。生成、重试和视觉审核均可能消耗额度；重启会将未完成任务标记为中断，不自动重放可能已计费的请求。
